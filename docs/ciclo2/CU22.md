# CU22 — Exportar reportes de citas médicas

Rama `feat/ciclo2-cu22-exportar-reportes`, desde CU21
`3415743bf7b9a1f8edf3b5e791520dbfec4df586`. Implementación local autorizada:
Dompdf 3.1.6 y cambios de Composer/Docker aprobados expresamente antes de incorporarlos.
Sin migraciones, commit/push, despliegue o acceso a PostgreSQL de Render.

## Objetivo, permisos y rutas

Descargar los agregados administrativos de CU21 en PDF y CSV. Administrador y
recepcionista tienen acceso; médico/paciente reciben 403 aun manipulando URL,
sin sesión se redirige al login. El middleware revalida cuenta activa y rol antes
de resolver el método. Otros métodos: 405 con Allow: GET. Formatos ajenos: 404.

- `GET /reportes/citas/exportar/pdf`.
- `GET /reportes/citas/exportar/csv`.

Las dos acciones aparecen junto a los filtros CU21. En celular permanecen
visibles y tienen un mínimo táctil de 44 px. Sus enlaces conservan exactamente
desde, hasta, medico_id, especialidad_id y estado ya validados en pantalla.

## Una sola fuente de datos y fórmulas

El controlador comparte un método consultar entre pantalla y exportaciones.
Siempre llama a ReporteCitaService::consultar. No hay SQL, validación de negocio
o fórmulas alternativas. El servicio y repositorio CU21 no se modifican.

ReporteCitaDocumento transforma ese único resultado en metadatos y presentación.
Los exportadores reciben el mismo objeto, sin acceso a PDO. Total, seis estados,
médicos, especialidades, días y situación de asistencia provienen del resultado.
No se cuentan eventos, no se duplican citas reprogramadas ni se unen especialidades
del médico. Los nulos históricos conservan «Sin registrar».

El rango es por inicio programado vigente, en America/La_Paz, con final exclusivo
del día siguiente. Las cifras describen estado actual, incluyen futuras cuando
corresponde y no son tasas clínicas ni conteos históricos de transiciones.
Todos los agregados de cada archivo conservan el snapshot de sentencia de CU21.

Entre abrir la pantalla y descargar, otro usuario puede modificar una cita:
la descarga vuelve a consultar el estado actual con los mismos filtros. No se
promete congelar datos entre solicitudes ni se guardan snapshots privados.

## PDF real

Dompdf genera PDF A4 horizontal, con DejaVu Sans local para Unicode español.
Incluye clínica, título, hora de generación local con offset, período/filtros,
resumen/estados/asistencia, tablas por médico/especialidad y días, explicaciones
y «Página n de N». Encabezados de tablas repetidos; filas sin división entre
páginas; nombres largos envueltos y márgenes para el pie. Un conjunto vacío
produce PDF válido con mensaje y ceros.

Plantilla HTML local, texto escapado con ENT_QUOTES/ENT_SUBSTITUTE. Sin PHP o
JavaScript embebidos, recursos remotos ni protocolos de carga: isRemoteEnabled,
isPhpEnabled e isJavascriptEnabled en false y allowedProtocols vacío. No hay
imágenes, URLs de usuario o estilos externos. Chroot restringido a fuentes locales.

Se crea un directorio aleatorio privado 0700 bajo el temporal del sistema;
el caché tipográfico y temporales se retiran en finally. El PDF se genera en
memoria antes de enviar cabeceras; no queda un archivo público ni una descarga
persistente en el servidor. Se comprueban firma PDF y fin de documento.

Límite defensivo del PDF: **500 filas agregadas**, sumando médicos, especialidades
y días. Es un límite de presentación y consumo del renderizador, no modifica el
período, SQL o fórmulas de CU21. Si se supera, devuelve 422 con un mensaje para
reducir filtros o usar CSV; no trunca cifras ni envía un PDF parcial. No se añaden
límites de fechas al reporte o al CSV. Se probaron nueve páginas/130 días y un
período de 2001 días que se rechaza como PDF y se descarga completo como CSV.

## CSV y Microsoft Excel

CSV auténtico generado con fputcsv: UTF-8 con BOM, separador `;`, registros CRLF,
comillas dobles y escape explícito vacío (compatible con PHP 8.4, sin depender
del escape predeterminado). Nueve columnas estables: Sección, Concepto,
Valor/Total y seis conteos. Las filas se identifican como Información, Filtro,
General, Estado, Médico, Especialidad, Día o Situación actual.

BOM permite reconocer UTF-8 en Excel. El punto y coma se elige para configuración
regional española; si Excel usa otro separador del sistema, importar como UTF-8
con delimitador punto y coma. No se añade una pseudofila sep= que altere el CSV.
Se conservaron acentos, ñ/Ñ, comillas, delimitadores y saltos internos mediante
round-trip del lector CSV nativo. No se implementa XLSX.

Todos los textos pasan por una función específica: detecta =, +, -, @ y variantes
de ancho completo tras espacios Unicode/caracteres de formato; también controles
iniciales, incluidos TAB, CR, LF y DEL. Se antepone TAB y apóstrofo para forzar
celda citada y tratamiento textual. Los delimitadores/comillas son escapados por
fputcsv, por lo que no se crean celdas nuevas. Los enteros y decimales legítimos
no reciben prefijos. El nombre sigue presente; los textos peligrosos incorporan
esta marca de seguridad. No se cambian los datos almacenados.

No se promete preservar esa protección si un usuario edita, transforma o vuelve
a guardar el archivo en otra herramienta. Microsoft Excel no está instalado en
este entorno: se probó la estructura y el parser CSV, no una sesión real de Excel.

El CSV se prepara por filas mediante generador y php://temp con umbral 1 MiB;
puede derramar al temporal del sistema fuera de public. Se cierra automáticamente
tras transmitirlo. No se cargan citas individuales ni se vuelven a contar datos.

## HTTP y errores

PDF: Content-Type application/pdf. CSV: text/csv; charset=UTF-8.
Content-Disposition attachment y nombres ASCII construidos solo con formato
permitido y las fechas validadas:
`clinica-vida-salud-reporte-citas-AAAA-MM-DD-a-AAAA-MM-DD.pdf` o .csv.
Content-Length binario correcto, Cache-Control private/no-store/max-age=0,
Pragma no-cache y nosniff existente.

Validar y generar ocurre antes de las cabeceras de descarga. Filtros inválidos:
422 HTML seguro sin attachment. Fallo inesperado: 500 con mensaje fijo y registro
genérico, sin datos SQL, DSN, credenciales o errores nativos. Se mantienen sesiones,
autenticación y CSRF del resto del proyecto. Exportar no escribe en PostgreSQL
ni añade eventos administrativos.

Versionar composer.json/lock; no vendor/. Usar install, no update para reproducir

## Docker y Render

Dockerfile conserva php:8.4-apache-bookworm, pdo_pgsql/mbstring, Apache, puertos,
sesiones y arranque existentes. Añade una etapa oficial composer:2.11.1, unzip
para extraer archivos y copia de composer.json/lock. En la imagen PHP comprueba
DOM, MBString e iconv, ejecuta install sin dev/plugins/scripts ni actualización y
verifica requisitos de plataforma. Un requisito ausente hace fallar el build.
La imagen PHP oficial habilita DOM/iconv por defecto; mbstring sigue compilándose
en el Dockerfile del proyecto. No se usa --ignore-platform-reqs.

.dockerignore permite los dos manifiestos y sigue excluyendo vendor local, .env,
sesiones, certificados, SQL, pruebas/artefactos y temporales. No se copia caché
local. Los temporales PDF quedan en el /tmp privado del contenedor.

Docker no está disponible: **solo se verificó estáticamente**, sin construir ni
ejecutar contenedores. No se cambió ningún servicio/configuración de Render ni
se probó su producción. Tampoco se ejecutaron migraciones o seed.
